# Voice Mode Experience & Talker/Thinker Architecture — Ambient Composer Glow, Frosted Teleprompter Karaoke & Full-Duplex Multi-Provider Realtime

Objective: Elevate Kite Code's native Voice Mode into a studio-grade, zero-friction conversational experience by (1) introducing a directional WebGL Ambient Horizon Glow + concentric ring anchored to the thread composer, a frosted-glass docked Teleprompter with 60 fps `AudioContext`-synced word karaoke and spring-damped auto-scroll, morphing call controls, and synthesized Web Audio sound cues; (2) wiring Kite's existing native full-duplex Realtime bridge (`src-tauri/src/voice_realtime.rs`, `src/lib/operator/voice/realtimeBridge.ts`) into the live session runtime with official multi-provider S2S Talker adapters (xAI Realtime, Google Gemini Live API `BidiGenerateContent`, OpenAI Realtime) cleanly decoupled from the heavy Thinker (Kite Threads, Subagents, Autonomous Agents, ODD delegation); and (3) adding inactivity auto-sleep quota safeguards, async post-call summary artifact cards, and a right-dock transcript viewer.
Branch: `feat/response-thread`.
Delivery strategy: `ask-on-risk` (8 reviewable ~250–400 line slices `T1–T8`; implementation gated on explicit user authorization before `T1`).
Test runner: `npx tsc --noEmit`, `npx vitest run src/lib/operator src/components/ArgosOrb.test.tsx src/components/ArgosStrip.test.tsx src/components/views/chat/ThreadVoiceMode.test.tsx src/components/views/chat/composer/VoiceModeFooterBar.test.tsx src/components/views/settings/ZedTab.test.tsx`, `cargo test --manifest-path src-tauri/Cargo.toml voice_realtime voice_audio`, `npm run verify:gate`, `node .kite/sanitizer/audit-references.mjs --check`.
Connected ODDs:
- Builds on: `odd/tasks/thread-voice-mode.md` (`T1–T21 [x]`), `odd/tasks/argos-voice-mode-roadmap.md` (`T0–T10 [x]`), and `odd/tasks/voice-mode-native-and-realtime-engine.md` (`T1–T8 [x]`).
Constraints: Does not modify protected zones (`src/components/TitleBar.tsx` mode switcher). Strictly adheres to Kite's 4-tier semantic radius contract (`AGENTS.md` §1, including `calc(var(--card-radius) - 1px)` concentric optical nesting) and 3-tier control height contract (`AGENTS.md` §2: `32px` standard / `28px`–`26px` compact). All external S2S transports use official documented APIs and user-supplied credentials only.

## Verified Baseline & Target Architecture

Auditing Kite Code's current Voice Mode implementation on `feat/response-thread` confirmed:

1. **Unwired Realtime S2S Runtime (`src/lib/operator/voice/realtimeBridge.ts`, `src-tauri/src/voice_realtime.rs`, `src/components/ArgosStrip.tsx`)**:
   - `RealtimeVoiceBridge` and `voice_realtime.rs` exist and pass unit tests, but have **zero runtime callers** in `ArgosStrip.tsx` or `ChatComposer.tsx`. Even when `voiceTransportMode === 'realtime'` is selected in `ArgosAudioSection.tsx`, live voice sessions execute 100% on the cascaded `STT -> LLM -> TTS` pipeline.
2. **Thread Voice Visual Presence & Karaoke (`src/components/views/chat/SingleThreadPane.tsx:762-787, 1112-1207`, `src/components/views/chat/composer/VoiceModeFooterBar.tsx`)**:
   - Empty voice threads render `.chat-voice-stage` with the interactive 112px WebGL2 orb, but once conversation turns appear, the composer drops back to a static footer bar with no ambient audio-reactive atmosphere, no docked glass teleprompter, and no morph entrance animation.
   - `SingleThreadPane.tsx:767-787` estimates karaoke word progress on a `120 ms` `Date.now()` heuristic (`length / 14.5`) rather than syncing against actual `AudioContext.currentTime` playback spans (`audioSpans`).
3. **Single-Cue Audio Feedback & No S2S Idle Quota Guard (`src/components/ArgosStrip.tsx:144-171`)**:
   - Only a single `660->880 Hz` chime exists; there are no distinct connect, disconnect, error, or reconnect-hold acoustic cues, and no configurable inactivity auto-sleep guard to prevent continuous S2S audio streams from burning quota when a user forgets an open mic.

## Specs

- **S1 — Ambient Horizon WebGL Composer Glow & Concentric Ring (`ComposerVoiceGlow.tsx`)**:
  - Verbatim:
    > "básicamente para tener una mejor experiencia de usuario en cuanto a vista, diseño, animaciones y todo eso al entrar al modo de voice mode."
  - Behavior:
    1. Render a pointer-events-none `ComposerVoiceGlow` layer positioned directly behind the top edge of the active thread composer card (`980×360` WebGL canvas with CSS radial-gradient fallback if WebGL is unavailable) plus a concentric outer border ring (`.kite-composer-voice-ring`, `inset: -1px` / optical nesting matching `AGENTS.md` §1 `var(--card-radius)`).
    2. **Directional Speaker-Aware Shader**: render 5 drifting soft domain-warped elliptical lobes, a subtle perspective halftone dot field (`smoothstep` band that recedes between turns and rises with speech activity), and light film grain. Smoothly steer the horizon light **left in cyan** when the user speaks (`micLevel > 0.04`, `650 ms` hold) and **right in the active voice's 3-stop palette (`deep`, `core`, `glint`)** when the assistant speaks (`speakerLevel > 0.05`, `450 ms` hold), adapting cleanly to both dark and light Kite themes.
    3. **Smart Content Avoidance**: observe the thread scroll container (`MutationObserver` + passive `scroll` + `resize`); whenever the latest message bottom is within `140 px` of the composer top, smoothly push the canvas downward (`bottom: -100px -> -218px`, `420 ms cubic-bezier(0.2, 0, 0, 1)`) so glow never obscures text legibility.
    4. **Low-CPU Adaptive Scheduler & Reduced Motion**: run at 60 fps during active speech/transitions, throttle to 30 fps (`>= 33 ms`) while calm, pause `requestAnimationFrame` completely when settled/muted (waking on audio activity events or exponential idle poll `120 -> 960 ms`), and freeze motion cleanly under `prefers-reduced-motion: reduce` or `html[data-motion='reduce']`.
  - Direction A refinement (`T9`): Entry activates a full-pane volumetric atmospheric stage (`data-testid="voice-stage-atmosphere"`) with ambient palette auroras, masked 22px spatial acoustic dot grid, and chromatic edge aura; draft view frames a `128px` kinetic `ZedOrb` inside a `168x168` orbiting reticle + dual sonar rings + staggered glass prompt pills; and `ComposerVoiceGlow` maintains vivid idle breathing (`0.24`/`0.34`), specular crest + halftone wave shader, and unclipped `360px` halo spread.
  - Checks: `ComposerVoiceGlow.test.tsx` verifying dark/light palette interpolation, directional speaker lean state machine, `<140px` push-down toggle (`data-pushed-down`), reduced-motion static render, and WebGL-unavailable fallback.

- **S2 — Docked Frosted-Glass Teleprompter & 60 fps `AudioContext`-Synced Karaoke (`VoiceTeleprompterDock.tsx`)**:
  - Verbatim:
    > "tener una mejor experiencia de usuario en cuanto a vista, diseño, animaciones y todo eso al entrar al modo de voice mode."
  - Behavior:
    1. **WAAPI Dock Entrance & Exit**: when Voice Mode is active on a thread, mount a frosted-glass docked drawer (`VoiceTeleprompterDock`, `rounded-t-card`, `backdrop-filter: blur(28px) saturate(1.5)` blending seamlessly into the composer card border) directly above `ChatComposer`. Animate entrance with Web Animations API (`height: 0 -> offsetHeight`, inner card `opacity: 0, translateY(28px) scale(0.98) -> 1, 0, 1` over `460 ms cubic-bezier(0.16, 1, 0.3, 1)` with `40 ms` inner delay) and exit over `260 ms cubic-bezier(0.4, 0, 1, 1)` (`0 ms` when reduced-motion is active).
    2. **Auto-Sizing & Collapsible Drawer**: measure content height via `ResizeObserver` and smoothly transition between `168 px` minimum and `min(45vh, 340px)` maximum (`300 ms`). Clicking Minimize collapses the transcript area via `grid-template-rows: 1fr -> 0fr` (`300 ms`) with opacity fade while keeping the compact Call Bar docked above the composer.
    3. **Real Audio-Synced Word Karaoke (`audioSpans` + `spokenChars`)**: replace the `120 ms` `Date.now()` heuristic in `SingleThreadPane.tsx:769-787` with an `AudioContext.currentTime`-driven progress calculator (`computeAudioSpanProgress`) updated via RAF at 60 fps. Format the first sentence as Lead (`15px` medium) and subsequent sentences in 2-sentence Body paragraphs (`14px`); spoken words transition smoothly (`200 ms ease-out`) to full foreground while upcoming words remain at `40%` muted opacity. On barge-in (`clearWithRamp`), freeze `spokenChars` at the exact heard character boundary.
    4. **Spring-Damped Cursor Auto-Scroll & Agent-Only Teleprompter Stage**: follow `[data-live-cursor="true"]` at `45%` of viewport height with exponential damping (`scrollTop += delta * 0.14`); immediately yield to manual wheel/touch scrolling and re-attach when the user scrolls back within `16 px` of the bottom. In Thread Voice Mode, live user speech appears exclusively inside the bottom composer input (`ChatComposer` / `liveTranscriptDraft.ts`); the top `VoiceTeleprompterDock` (`showUserTurns={false}`) is reserved exclusively for the Agent's state and spoken output (reactive wave ribbon shifting cyan when hearing the user, `"Escuchando tu voz…"`, `live-transcribing-turn` `"Transcribiendo tu voz"`, `"Pensando…"`, non-blocking `statusHint`, and Argos karaoke reply), never duplicating user text in a second upper box. Optional opt-in `showUserTurns={true}` keeps standalone floating/fade compatibility where requested.
  - Direction A refinement (`T10`): Teleprompter dock shifts to sheer translucent spatial glass (`rgba(..., 0.34..0.62)` + specular top rim) so the WebGL aurora shows through; editorial karaoke typography rises to `20px` bold lead / `16px` body with blur-to-crisp word reveal and active cursor glow behind a vertical edge fade mask; `VoiceWaveRibbon.tsx` renders multi-harmonic Canvas 2D acoustic silk waves (`hero` in idle, compact `horizon` during speech); and `VoiceCallBar.tsx` adds a live pulsing speaker beacon.

- **S4 — Synthesized Web Audio Sound Design (`src/lib/operator/voice/voiceSoundCues.ts`)**:
  - Behavior:
    1. Implement a zero-asset Web Audio acoustic cue module respecting user voice volume (`voiceVolume` / `ttsVolume`) and mute state, routed through a warm lowpass feedback delay (`2200 Hz`, `90–100 ms` delay, `0.14–0.18` feedback):
       - **Connect chime**: dual ascending sine sweep (`260→310 Hz` at `0 ms` + `340→420 Hz` at `55 ms`).
       - **Disconnect chime**: dual descending sine sweep (`380→320 Hz` at `0 ms` + `280→220 Hz` at `55 ms`).
       - **Error cue**: muted low double-thud (`147→91 Hz` at `0 ms` and `160 ms`).
       - **Reconnect hold pulse**: subtle `300→340 Hz` pulse every `2,000 ms` while reconnecting, suppressed automatically when assistant audio is still playing or user speech occurred within `900 ms`.
    2. Replace the single hardcoded `playSoftReadyChime()` in `ArgosStrip.tsx` with `voiceSoundCues`.
  - Checks: `voiceSoundCues.test.ts` verifying oscillator scheduling, volume `0` no-op suppression, reconnect interval cleanup, and AudioContext teardown.

- **S5 — Runtime Full-Duplex Talker ↔ Thinker Engine & Official Multi-Provider S2S Transports**:
  - Verbatim:
    > "Básicamente cómo se siente es literalmente como una conversación. Yo hablo, el agente responde instantáneamente, y así."
    > "Quiero que comencemos a avanzar mucho más rápido en el modo de voz nativo."
  - Behavior:
    1. **Wire `RealtimeVoiceBridge` into Live Session Runtime (`ArgosStrip.tsx`, `voiceSessionStore.ts`, `realtimeBridge.ts`)**: when `voiceTransportMode === 'realtime'`, open the native Rust full-duplex session on `startSession()`, stream native `cpal` / worklet PCM16 audio frames directly into `voice_realtime.rs`, and play incoming 24 kHz PCM16 audio through a dedicated low-latency `Pcm24kPlayer` (`AudioContext({ latencyHint: 'playback' })` + `AnalyserNode` speaker-level feed + `20 ms` `clearWithRamp()` barge-in + exact `audioSpans` timestamps for `S2`). Automatically downgrade to `cascaded` mode with an honest non-blocking notice if realtime credentials or connection fail.
    2. **Official Multi-Provider S2S Talker Adapters (`src-tauri/src/voice_realtime.rs`)**: support selecting the official Realtime Talker provider in `ArgosAudioSection.tsx`:
       - **xAI Realtime** (`wss://api.x.ai/v1/realtime`, 24 kHz PCM16 in/out, `server_vad`, `conversation.item.truncate`).
       - **Google Gemini Live API** (official `BidiGenerateContent` WebSocket via Google AI Studio / Vertex AI API key, 16 kHz PCM16 in -> 24 kHz PCM16 out, `realtimeInputConfig.automaticActivityDetection`, `inputAudioTranscription`, `outputAudioTranscription`, native tool declarations, server barge-in `interrupted` -> `clear_audio`).
       - **OpenAI Realtime** (`wss://api.openai.com/v1/realtime`, 24 kHz PCM16 in/out, `server_vad`).
    3. **Talker ↔ Thinker Async Orchestration Protocol**:
       - Keep the Talker focused on instantaneous spoken dialogue (`~250–450 ms`) and lightweight read-only checks (`peek_*`).
       - Expose 4 high-level delegation tools to the Talker: `call_thinker_agent` (dispatches real work asynchronously to the active Thread / `dispatch_run` Subagent / Autonomous Agent using the user's configured coding model — the **Thinker** — so the Thinker consumes 0 tokens during casual chat), `cancel_thinker_agent`, `set_progress_updates(enabled)` (controls whether background Thinker progress notes are spoken aloud), and `hang_up`.
       - Fold background Thinker step updates through `VoiceTurnArbitrator` so the Talker narrates concise milestones without interrupting the user.
    4. **Selectable Antigravity CLI Subscription Models & Honest Fallback Reporting (`T13`)**:
       - Support choosing any subscription model dynamically discovered from `agy models` via `list_chat_provider_models` + searchable `<ModelSearchField>` in Settings → Proveedor → Antigravity (plus custom exact ID input), defaulting to **`gemini-4-hydrogen-low`** (~2.51 s warm vs ~6.70 s cold).
       - Prewarm headless `agy --input-format stream-json` (`prewarm_operator_agent`) when Voice Mode opens (`sessionPrewarm.ts`), instruct the headless planner never to invoke external MCP tools directly (`prompt.ts` Rule `2b` — delegate implementation work to smarter Thinker coding models via `propose_task` / `spawn_subagent` / `launch_thread`), and surface real `fallbackReason` / `zedAssistantFailureMessage` notices when an LLM provider fails instead of masking errors with `"No reconocí una acción concreta para ejecutar en el sistema."`.
  - Checks: Rust unit tests (`cargo test --manifest-path src-tauri/Cargo.toml voice_realtime`) covering xAI, Gemini Live `BidiGenerateContent`, and OpenAI Realtime frame serialization/parsing, barge-in truncation, and error redaction; Vitest tests (`realtimeBridge.test.ts`, `pcm24kPlayer.test.ts`, `ArgosStrip.test.tsx`) covering live runtime activation, `call_thinker_agent` async dispatch, `clearWithRamp` 20 ms fade, and automatic `cascaded` fallback.
