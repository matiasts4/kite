# Context optimization engine (`kite-ctx`)

Objective: provide a modular, zero-ML Rust context optimization crate (`src-tauri/crates/kite-ctx`) integrated with the `kite` CLI (`kite ctx`), multi-agent hooks, inter-agent compressed handoffs, KV-cache alignment, and the desktop telemetry panel.
Branch: `feat/response-thread`. Delivery strategy: `ask-on-risk` (git commits held cleanly in working tree due to parallel uncommitted work on `feat/response-thread`). Test runner: `cargo test --manifest-path src-tauri/Cargo.toml -p kite-ctx`, `cargo test --manifest-path src-tauri/Cargo.toml`, `npx tsc --noEmit`, `npx vitest run`, and `node .kite/sanitizer/audit-references.mjs --check`.
Does not change the title-bar mode switcher.

## Specs

S1. Modular Cargo workspace crate (`src-tauri/crates/kite-ctx`) with zero ML dependencies.
User words: "hacerlo bastante separado. Para poder ir mejorándolo en gran parte. Quiero decir, tomarlo como un, subrepositorio. Esto no quiere decir que hay que crear un nuevo directorio completamente desde cero y luego conectarlo, sino que eh, ¿consideras que tenemos que tenerlo un poco modular, separado? Pero, tampoco tanto. Eh, simplemente para que tengamos buenas prácticas de código y sea más modificable en un futuro."
1. `src-tauri/Cargo.toml` declares a Cargo workspace including `.` and `crates/kite-ctx`.
2. `kite-ctx` compiles as a standalone pure-Rust library crate with zero Tauri/WebView or ONNX/ML dependencies (<5 MB runtime footprint), linked by both the `kite` CLI binary and the `kite-code` desktop binary.
3. All persistence lives in a shared local SQLite database (`~/.kite/ctx/store.db`, overrideable via `KITE_CTX_DB_PATH` for isolated tests).
Checks: `cargo test --manifest-path src-tauri/Cargo.toml -p kite-ctx`.

S2. Stage 0 lossless compaction and deterministic command output filters.
User words: "formas de ahorrar tokens. O consumo. Básicamente para. Optimizar esto, último... consumir menos tokens, utilizar más eficazmente las cuotas. de los agentes y que también sea más rápido, claramente."
1. `kite_ctx::lossless` implements deterministic transforms with exact round-trip verification where applicable: `strip_ansi`, `collapse_runs` (`... (repeated N times)`), `fold_repeated_blocks` (`... (repeats K lines from D lines back)`), `search_heading` and `search_dir_heading` (grouping `path:line:content` search output by shared file/directory headers), `diff_strip_index`, and blank-line minification. If a transform does not reduce byte/token size, the original text is returned unchanged.
2. `kite_ctx::cmd_filters` implements deterministic command-aware output filters for `git` (`status`, `diff`, `log`), `cargo` (`test`, `build`, `check`, `clippy`), `vitest`/`jest`/`npm`/`pnpm`, `tsc`, `pytest`, `grep`/`rg`, and directory listings (`ls`/`tree`), stripping passing test noise, grouping compiler diagnostics by file, and preserving all failure signals and exit codes.
Checks: unit tests in `kite-ctx` asserting token savings, failure preservation, and lossless round-trip inversion.

S3. Tabular JSON compaction, dictionary value factoring, and statistical anchor selection (`crusher`).
User words: "qué hace con respecto a la comprensión de contexto o de los tokens, para reutilizar y demás? Eso también es algo importante que podemos revisar... crear un nuevo motor, nosotros mismos."
1. Stage 1 (Lossless Tabular & Dictionary Compaction): uniform JSON object arrays ($\ge 80\%$ shared keys) are encoded into compact `[N]{col:type,...}` tabular headers with CSV rows and `@col=["val0","val1"]` dictionary legends for repeated string values when byte savings are $\ge 15\%$.
2. Stage 2 (Statistical Anchor Selection + Reversible Sentinel): when arrays exceed the item/token budget (`min_items = 5`, `max_items = 15`), `crusher` allocates `front`, `middle`, and `back` anchor slots by data pattern (`SearchResults`, `Logs`, `TimeSeries`, `Generic`) and ranks middle candidates by information density:
   $$\text{Score}(x) = 0.4 \cdot \text{ValueUniqueness}(x) + 0.3 \cdot \text{NormalizedLength}(x) + 0.3 \cdot \text{StructuralUniqueness}(x)$$
   preserving errors/anomalies and appending a `<<ccr:HASH>>` marker referencing the full original payload in `ccr_store`.
Checks: unit tests in `kite-ctx` covering uniform JSON arrays, dictionary factoring, anomaly preservation, and CCR marker generation.

S4. Session-scoped file read deduplication, structural read modes, and lifecycle tracking (`read_cache`).
User words: "integrar, pero para todos los agentes. Para ahorrar contexto. Eh, reutilización de tokens. Y cosas de ese estilo."
1. `kite_ctx::read_cache` records `(session_id, canonical_path, sha256, mode, line_range, turn_index)` in SQLite.
2. When the same session re-reads an unchanged file covering an already-delivered range, `read_cache` returns a compact reference stub (`[Unchanged since read #N — sha256:<short> lines:<start>-<end>. Pass --fresh or kite ctx retrieve <hash> for full text]`).
3. When a previously read file has been modified on disk, `read_cache` marks the older read `STALE`, stores the new snapshot, and in `diff` (or `auto` re-read) mode returns only the unified diff delta against the previous read alongside updated line numbers.
4. Supports read modes `full`, `signatures`, `map`, `diff`, and `lines:N-M`.
Checks: unit tests in `kite-ctx` verifying first read, unchanged re-read stub, post-edit `diff` delta, and `signatures`/`map`/`lines:N-M` extraction.

S5. Reversible Compress-Cache-Retrieve (`ccr_store`).
User words: "usar la memoria entre sesiones o todo ese tipo de cosas. Entonces, quiero que comencemos a, plantear cómo se armará este. Em. Motor. También con la reutilización de tokens, y todo ese tipo de cosas."
1. `kite_ctx::ccr_store` stores original uncompressed payloads keyed by 16-hex-character SHA-256 hashes in SQLite with configurable TTL (default 3600s) and LRU capacity eviction.
2. Bare `<<ccr:...>>` strings are rejected as originals to prevent recursive placeholder poisoning.
3. `kite ctx retrieve <hash> [--lines N-M] [--search <pattern>]` recovers the exact original payload or a filtered slice on demand.
Checks: unit tests in `kite-ctx` verifying store, exact retrieval, line-slice retrieval, pattern search, TTL expiration, and placeholder guard.

S6. Compressed inter-agent handoffs (`shared_ctx`) and cross-session tool cache with hierarchical scoping.
User words: "usar la memoria entre sesiones o todo ese tipo de cosas... que nos serviría a integrar, pero para todos los agentes. Para ahorrar contexto. Eh, reutilización de tokens."
1. `kite_ctx::shared_ctx` implements compressed inter-agent context sharing (`put(key, content, agent, provider, scope)` and `get(key, full)`): storing content automatically runs the compression pipeline, persists both the compressed summary and the original payload with provenance metadata (`source_agent`, `source_provider`, `created_at`, `original_tokens`, `compressed_tokens`), returns the compressed representation by default (`get(key, false)`), and returns the verbatim original when `full = true`.
2. Entries support hierarchical scopes (`User`, `Project`, `Session`, `Agent`, `Turn`) and cross-session tool/command output caching keyed by `(workspace_root, git_head_or_file_hash, tool_name, canonical_args_hash)` so repeated inspections across agents or sessions reuse compressed outputs without re-execution.
Checks: unit tests in `kite-ctx` verifying `put`/`get` round-trips, provenance metadata, scope isolation, and cache invalidation when file/tree hashes change.

S7. KV-cache prefix alignment and net-cost break-even guard (`kv_aligner`).
User words: "utilizar más eficazmente las cuotas. de los agentes y que también sea más rápido, claramente."
1. `kite_ctx::kv_aligner` provides structural (non-mutating) detection of volatile tokens in system prompts (UUIDs, ISO-8601 timestamps, JWTs, dynamic hex hashes) that would bust provider prefix caches.
2. Tracks `frozen_message_count` per session lineage so historical turns already cached by providers (Anthropic 90% read discount, OpenAI 50%, Gemini 75%–90%) are never mutated retroactively unless the net-cost break-even formula $\Delta T \cdot (w + r(R - 1)) > P_{\text{alive}} \cdot (w - r) \cdot (S + \Delta T)$ holds as cache TTL decays.
Checks: unit tests in `kite-ctx` verifying volatile-token detection, prefix freeze boundary calculation, and net-cost break-even gating.

S8. `kite ctx` CLI subcommands and multi-agent hook/rule installer (`hooks`).
User words: "integrar, pero para todos los agentes... Con tal de que se adapte correctamente a nosotros, a nuestra aplicación y al consumo" / "implementar en los agentes" / "si claro, la idea es que quede completamente habilitado y funcional para utilizar y probar"
1. The `kite` CLI binary (`src-tauri/src/bin/kite.rs`) exposes `kite ctx` with subcommands:
   - `kite ctx read <path> [--mode auto|full|signatures|map|diff|lines:N-M] [--session <id>] [--fresh]`
   - `kite ctx exec [--session <id>] [--agent <name>] [--model <name>] -- <command...>` (executes command, compresses stdout/stderr, preserves exit code, records ledger entry)
   - `kite ctx compress [--kind auto|json|diff|grep|log|text]` (reads stdin, writes compressed stdout)
   - `kite ctx retrieve <hash> [--lines N-M] [--search <query>]`
   - `kite ctx share put <key> [--agent <name>] [--scope project|session|agent]` and `kite ctx share get <key> [--full]`
   - `kite ctx stats [--project] [--json] [--reset]`
   - `kite ctx init [--agent claude|antigravity|cursor|codex|gemini|opencode|grok|copilot|agents|all] [--check]` (configures non-destructive `PreToolUse` command hooks and `kite-ctx/SKILL.md` / rule instructions across all detected local agent directories, including both `.gemini/antigravity` and `.gemini/antigravity-cli`, Claude skills/hooks, Codex, Gemini, Cursor, OpenCode, Grok, Copilot, and `.agents`).
2. Kite desktop startup housekeeping (`dispatch_wire::server`) and agent spawns (`chat::runtime::spawn` and `terminal::spawn`) automatically sync `kite-ctx` skills/hooks alongside `kite-dispatch` and `kite.exe` shim, and propagate `KITE_SESSION_ID`, `KITE_AGENT_NAME`, `KITE_PROVIDER`, `KITE_MODEL`, and `KITE_PROJECT` environment variables to spawned thread and PTY agents.
Checks: CLI & crate unit tests covering multi-target hook/skill installation, dual Antigravity roots, and thread/PTY runtime env attribution.

S9. Unified savings ledger and desktop telemetry tab integration.
User words: "Todas estas cosas tenemos que evaluar... Con tal de que se adapte correctamente a nosotros, a nuestra aplicación y al consumo, y que claramente nos ayude. a, consumir menos tokens, utilizar más eficazmente las cuotas. de los agentes" / "Medir, pero luego. En lo que sería la parte de recursos o rendimiento. Medir con ese componente que indica. Ahorro o cosas. De cada. Funcionalidad."

2. `src-tauri` exposes a Tauri command `fetch_context_monitor` reading directly from `kite_ctx::ledger` (no external HTTP proxy required, working for all providers including OAuth sessions).
3. `SystemResourcePopover.tsx` (`ContextTab.tsx`) displays live context & token savings from `fetch_context_monitor`, including a `Por funcionalidad` breakdown and a quick summary/shortcut from `OverviewTab.tsx`.

S10. Mandatory multi-agent `PreToolUse` / `BeforeTool` / plugin command interception and compound shell chain rewriting.
User words: "inclusive las que tienen que ver con que esfuercen o mejoren la capacidad de uso para los agentes, es decir que sea como más forzado hacerlo y no depender tanto de la, de que lean las skills porque eso no es. Algo que siempre harán. Quiero decir, son instrucciones, es correcto, pero no siempre las leen o ejecutan."
1. `kite ctx init` installs native mandatory pre-execution hooks and plugins across all supported agent ecosystems in addition to `SKILL.md` and rules:
   - **Claude**: `~/.claude/settings.json` (`hooks.PreToolUse` with matcher `Bash` calling `kite ctx hook-rewrite --agent claude`).
   - **Antigravity**: `~/.gemini/config/plugins/kite-ctx/` containing `plugin.json`, `hooks.json` (`hooks.PreToolUse` with matcher `run_command` calling `kite ctx hook-rewrite --agent antigravity`), and `rules/AGENTS.md` (plain markdown rule loaded into every Antigravity session).
   - **Codex**: `~/.codex/hooks.json` (`hooks.PreToolUse` with matcher `Bash` calling `kite ctx hook-rewrite --agent codex`).
   - **Gemini CLI**: `~/.gemini/settings.json` (`hooks.BeforeTool` with matcher `run_shell_command` calling `kite ctx hook-rewrite --agent gemini`).
   - **Cursor**: `~/.cursor/hooks.json` (`hooks.preToolUse` with matcher `Shell` calling `kite ctx hook-rewrite --agent cursor`).
   - **OpenCode**: `~/.config/opencode/plugins/kite-ctx.ts` (TypeScript plugin hooking V1 `tool.execute.before` and V2 `ctx.tool.hook("execute.before")` to rewrite shell commands via `kite ctx hook-rewrite --agent opencode --command <cmd>`).
   - **Copilot**: `~/.copilot/hooks/kite-ctx.json` (`version: 1`, `hooks.PreToolUse` calling `kite ctx hook-rewrite --agent copilot`).
2. `kite ctx hook-rewrite [--agent <claude|antigravity|codex|gemini|cursor|opencode|copilot|auto>] [--command <raw_cmd>]` parses each agent's native hook payload (including UTF-8 BOM stripping and fail-open passthrough when a command is not rewritable) and emits the exact protocol-specific rewrite JSON (`updatedInput`, `overwrite.CommandLine`, `hookSpecificOutput.tool_input`, `updated_input`, `modifiedArgs`, or `{"command": ...}`).
3. `rewrite_hook_command` splits compound shell chains connected by top-level `&&` or `;` outside quotes and rewrites each eligible segment independently (for example `cd src-tauri && cargo test -p kite-ctx` -> `cd src-tauri && kite ctx exec -- cargo test -p kite-ctx`) while leaving pipes (`|`), redirections (`>`), subshells, and assignments untouched.
Checks: unit tests in `kite-ctx` covering every agent protocol payload, compound `&&`/`;` chain rewriting, and multi-target plugin/hook file installation.

S14. Flag-aware subcommand resolution and high-yield `git`/`cargo`/`npx`/`search` output filters (Phase 1).
User words: "Sí, quisiera que armáramos un plan estratégico básicamente de las correcciones y mejoras para optimizar todo este tema... Tenemos que primero. Eh, planear. Luego implementar. Y luego. Examinar qué tal va la implementación como tal, cuáles son. Los resultados y qué más podemos continuar mejorando." / "Sí, creo que arranca con la implementación."
1. `cmd_filters` provides a shared flag-aware subcommand resolver (`resolve_subcommand_index`, `canonical_command_label`) that skips leading value-taking flags (`git -C <dir> -c <k=v> --git-dir <d> --work-tree <d>`, `npx --prefix <dir> -p <pkg> -c <cmd>`, `npm/pnpm/yarn/bun --prefix/--dir/--cwd/-C/--filter <val>`, `cargo +toolchain --manifest-path/--target-dir/-C/-Z/--config <val>`). `cmd_filters`, `hooks::rewrite_single_segment` (skipping `git -C <dir> commit/rebase/...`), `discover`, and `ContextEngine::filter_command_with_telemetry` ledger labels all reuse this resolver.
2. `filter_git` routes `grep` to `filter_search`, folds lockfile/generated hunks (`package-lock.json`, `Cargo.lock`, `yarn.lock`, `pnpm-lock.yaml`, `*.min.js`, `*.min.css`) in `diff`/`show` with a per-file `stat` summary + bounded hunks + `<<ccr:HASH>>` spill when oversized, and groups large/short-form `status` listings by top-level directory while keeping small outputs untouched.
3. `filter_search` (`git grep`, `rg`, `grep`) caps oversized match dumps (`> 80` lines or `> 6,000` chars) with balanced per-file coverage across distinct files and spills the full raw output to `ccr_store` (`<<ccr:HASH>>`).
4. `filter_cargo` (`check`, `build`, `clippy`) preserves `error` diagnostic blocks in full while deduplicating repeated warnings across targets and condensing verbose multi-line `warning:` blocks into single-line `WARN file:line:col — msg` entries (with `<<ccr:HASH>>` spill when oversized).
Checks: `cargo test --manifest-path src-tauri/Cargo.toml -p kite-ctx`.

S15. Universal Auto-CCR spill ceiling for oversized command outputs (Phase 1).
1. Any command executed through `ContextEngine::filter_command_with_telemetry` whose post-filter output exceeds `MAX_EXEC_OUTPUT_CHARS` (`16,000` chars / `~4,000` tokens) automatically stores the full ANSI-stripped raw output in `ccr_store` and returns a bounded preview containing head lines, deduplicated middle error/failure/panic/warning lines, tail lines, and a `<<ccr:HASH>>` retrieval directive.
2. Small and medium command outputs (`<= 16,000` chars) pass through the ceiling untouched, and exit codes and error diagnostics are never dropped.
Checks: `cargo test --manifest-path src-tauri/Cargo.toml -p kite-ctx`.

S16. Accurate transcript discovery and clean runtime thread/test attribution (Phase 1).

2. `assemble_thread_context` (`src-tauri/src/chat/runtime/turn.rs`) resolves `agent_name` from `subagentRole` or `swarmMemberName` (falling back to provider or `"thread"`, never `thread.title`), and `runtime_tests.rs` isolates `KITE_CTX_DB_PATH` in a temporary directory so unit tests never pollute `~/.kite/ctx/store.db`.
