# Zed Assistant — Execution Truth, Prompt-Throw Animation & Multi-Agent Orchestration
Branch: `feat/ui-composer` | Delivery strategy: `ask-on-risk` | Test runner: `npx vitest run`
Verification: `npx tsc --noEmit`, `npx vitest run`, `node .kite/sanitizer/audit-references.mjs --check`

## Specs

- **S1 — Granular Execution Trace & Post-Condition Verification Truth**:
  - User verbatim: `"Todo sobre el. Asistente S.E.D.S. y en cómo detectamos las trazas habilidades de ejecución de eventos. Es decir. ¿Cómo detectamos actualmente que se ejecutan? ... Para esto, se requiere una detección bastante , granular de cada una de las cosas"`
  - `OperatorTurnTrace` (`src/lib/operator/trace/types.ts` & `trace.ts`) must persist `plan?: OperatorPlan` and `receipts: ActionReceipt[]` populated from executed actions, plus expose `exportTracesJson()` and `readDiskTracesJsonl()` so CLI inspection works without `window`.
  - Every executed operator action must emit an `action.verify` trace event.
  - `CodeWorkspace.tsx` must only register a spawned terminal in `terminalRegistry` after `start_terminal` IPC resolves (propagating `ok: false` on failure), and `closeTerminals` (`appOperatorController.ts`) must only mark a terminal exited after `terminate_terminal` IPC resolves, with `src-tauri/src/terminal.rs` returning `terminated: bool` reflecting whether a live session existed.
  - When a plan's actions are filtered out by safety guards resulting in `actions: []`, `executePlan` must not report `overallSuccess: true` with a false affirmative action reply.
  - `runOperatorTurn` (`src/lib/operator/index.ts`) must close opened `runLedger` runs via `completeRun`.

- **S2 — Updated Zed Execution & Diagnostics Documentation (`docs/` and `odd/tasks/`)**:
  - User verbatim: `"era el asistente zed, revisa en docs"`
  - `odd/tasks/zed-assistant-execution-audit-guide.md` and `docs/zed-assistant/execution-and-diagnostics.md` must match the v2 trace implementation (`kite.operator.trace.v2`, `MAX_TURNS = 200`, JSONL persistence under `%APPDATA%\Kite Code\operator-traces\<YYYY-MM-DD>.jsonl`, `exportTracesJson()`, and a working Node CLI command that reads disk JSONL traces rather than returning 0 turns when `window` is undefined).

- **S3 — Terminal Default Decontamination (No Unrequested Grok Launches)**:
  - User verbatim: `"Se equivocaba a veces también en las cosas que yo le pedía, por ejemplo, le decía abre dos terminales, pero me las abría con Grok."`
  - Default `engine` across `OpenTerminalsActionSchema` (`contract.ts`), native tool definitions, `openTerminals.ts`, and `appOperatorController.ts` must be `'powershell'` unless the user explicitly requests an AI agent provider (`grok`, `claude`, `codex`, `antigravity`, `opencode`) or `spawn_subagent`.
  - Engine detection in `heuristic.ts` must parse the open/agent clause rather than letting words inside a task prompt hijack the engine, and shell commands (`"abre una terminal y ejecuta git status"`) must remain `'powershell'` unless an agent is explicitly named.

- **S4 — Reliable Close Semantics, Polarity & Target Filtering**:
  - User verbatim: `"antes eran que no cerrabas ciertas cosas."`
  - Negative imperatives (`"no cierres las terminales"`, `"no abras dos terminales"`) must be blocked from triggering `close_terminals` or `open_terminals`.
  - Subordinate clauses (`"abre una terminal para cerrar los issues"`) must classify by the main clause verb (`open_terminals`), not `close_terminals`.
  - Numeric target extraction (`extractTerminalIndices`) must require a compatible terminal/agent noun or context so `"cierra la pestaña 2"` does not close agent terminal 2.
  - In `appOperatorController.ts` `closeTerminals`, provider/engine filters (`antigravity`, `claude`, `opencode`, `grok`, `codex`) must be evaluated before generic `abiertas`/`activas` wildcards, and `countLimit` must slice from the start (`.slice(0, countLimit)`).
  - Stopping a terminal from `AgentTerminalPane.tsx` must also call `markTerminalExited(sessionId)` so `terminalRegistry` stays synchronized.

- **S5 — Signature Prompt-Throw Animation (Zed → Terminal & Terminal A → Terminal B)**:
  - User verbatim: `"Algo que me gustaría mejorar eso sí, que es clave, es la animación de cuando arroja. Un prompt a alguna gente o a alguna terminal. Es clave esa animación."`
  - `appOperatorController.injectPrompt` must dispatch `kite:dispatch-prompt-projectile` (and `pulseZedOrb()`) and deliver the prompt via `kite:terminal-staged-prompt` so injecting a prompt into any open terminal or agent always plays the flight animation.
  - `PaneNodeRenderer.tsx`, `TerminalView.tsx`, and `AgentTerminalPane.tsx` must render `data-session-id` and `data-pane-id` attributes so `PromptProjectileOverlay.tsx` resolves the exact target and source panes instead of falling back to the last terminal pane.
  - `PromptProjectileOverlay.tsx` must render a prompt preview capsule/comet pill along the arc, support staggered multi-shot launches (`staggerMs`) for multi-terminal dispatches, support Terminal-A-to-Terminal-B flight (`sourceSessionId` / `sourcePaneId` → `targetSessionId` / `targetPaneId`), and emit `kite:prompt-landed` on impact.
  - `TerminalView.tsx` and `src/styles/terminal.css` must play an arrival impact pulse (`.terminal-canvas-area--impact` with `var(--accent)` glow and `prefers-reduced-motion` safety) when `kite:prompt-landed` fires.

- **S6 — Proactive Agent Completion & Attention Watcher (Voice + Notifications)**:
  - User verbatim: `"Que pueda hablarme cuando termine algún agente."`
  - A proactive watcher (`src/lib/operator/proactiveWatcher.ts`) must subscribe to `kite:terminal-agent-update`, detect state transitions (`working -> done`, `working -> waitingForYou`, and unexpected error exit), speak a concise Spanish status via `ttsNarrator.speak` (with deduplication and suppression of manual closes), and invoke `notifications_report_attention` (`src-tauri/src/notifications.rs`) so the in-app notification badge, chime, and toast also trigger.

- **S7 — Multi-Agent ODD Handoff & Terminal-to-Terminal Piping (`handoff_to_agent`)**:
  - User verbatim: `"la, lo de la orquestación multiagente es algo que sí quiero realizar. Por ejemplo, yo utilizo mucho lo que sería muchos tipos de agentes, ya sea de OpenCode, AntiGravity o otro proveedor. Con algunos planeo y a otros delego. Es por esto que es, pido a algunos que creen, por ejemplo, los ODD y a otros que lo implementen. Entonces sería bastante útil poder decirle al asistente, pásale el el ODD de la terminal llamada tanto a otro agente que abrirás. De tal cosa, y bueno. Le entregaría la tarea básicamente para que dé, hiciera todo."`
  - Add `handoff_to_agent` to `ActionSchema` (`contract.ts`), planner (`heuristic.ts`, `prompt.ts`, `llm.ts`), and executor (`executor/actions/handoffToAgent.ts`).
  - Given a source terminal (by codename/title, index, or engine) and a target agent (existing terminal or a new agent terminal to spawn with the specified provider such as `opencode`, `antigravity`, `claude`, `codex`, `grok`), extract the ODD path (`odd/tasks/<slug>.md` or `.kite/tasks/<slug>.md`) or terminal summary from the source terminal's rolling buffer (`getTerminalRollingBuffer`), spawn the target agent terminal if requested, and dispatch the handoff prompt with a projectile flying from the source terminal to the target terminal.

- **S8 — Spatial Control of Panes & Auto-Adjust / Equalize Dimensions (`manage_pane_layout`)**:
  - User verbatim: `"El tema del control espacial de Paines también es bastante útil. Diría que... es una herramienta que sí nos serviría. También, por ejemplo, el autoajuste. A veces, eh, se hace un resize de algunas ventanas o terminales, es decir, yo las muevo. Y es bastante útil que el agente también pueda autoajustar todo para que quede todo de las mismas dimensiones."`
  - Add `manage_pane_layout` action (`equalize`, `split-horizontal`, `split-vertical`, `focus`, `zoom`) in `contract.ts`, `heuristic.ts`, `prompt.ts`, `executor/actions/managePaneLayout.ts`, and `CodeWorkspace.tsx` (`equalizeSplitRatios` to reset all pane split ratios to equal dimensions, plus split/spotlight/fullscreen).

- **S10 — Toast surfacing when the planner model fails (quota / no response)**:
  - When the Zed operator's LLM provider fails (quota exhaustion, HTTP 402/429, timeout, or no response) and the turn falls back to heuristics, the user must see an ambient error toast (`toast.error('Asistente Zed', …)`) via `turn.end` trace `error`, not only a buried note on the floating orb.
  - `zedAssistantFailureMessage` (`src/lib/operator/assistantFailureNotice.ts`) maps provider `fallbackReason` to concise Spanish copy; `runOperatorTurn` attaches it to `turn.end` even when local recovery still reports `overallSuccess: true`.

- **S9 — Workspace Switching & View Mode Navigation Only (No Sidebar Close or Git Action Bloat)**:
  - User verbatim: `"A ver, control de superficies, esto es algo bastante, puntual. Diría que lo más práctico y la mejor funcionalidad sería poder cambiar de proyecto, es decir, moverse hacia otro proyecto, desplegar, terminar desde ahí, eso es bastante útil, y sí quiero hacerlo, pero diría que nos limitemos solamente a eso. Eh, por ejemplo. No creo que sea tan necesario cerrar la sidebar para hacer eso, sino que limitémonos a que pueda controlar los workspace. Es decir, moverse. entre ellos. Y cambiar mi visualización."`
  - User verbatim: `"El tema de las acciones rápidas por Git diría que no es algo tan imperativo porque, actualmente delego a agentes es hacer cosas, por ejemplo. Me sirve que el asistente pueda abrir un nuevo agente y inyectar el prompt que le digo literalmente."`
  - Add `switch_workspace` action (`workspaceQuery`, optional `viewMode`) to switch across workspaces (`kite:select-workspace`) and view modes (`kite:navigate-mode`: `agents`, `code`, `threads`) and allow spawning/controlling terminals in the newly selected workspace without dropping events. Do NOT add sidebar close or Git quick actions.
