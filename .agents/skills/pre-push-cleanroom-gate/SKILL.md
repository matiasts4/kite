## Activation Contract

Load ONLY when the user explicitly triggers a pre-commit review, commit-slice preparation, release check, or `git push` gate. Never run automatically on unrelated coding turns.

## Hard Rules

- **Clean-room hygiene first**: Run `node .kite/sanitizer/audit-references.mjs --check` (and `--all` before pushing a release branch). Never stage or push unless the output ends with `[AUDIT CLEAN]`.
- **Protect internal and unrelated files**: Never stage `.kite/`, `.codegraph/`, `.env*`, secrets, build artifacts, or unrelated parallel ODD changes from a dirty working tree (`never git add -A` or `git add .`).
- **Zero AI attribution**: Commit messages must use Conventional Commits (`feat(scope): ...`, `fix(scope): ...`, `docs(scope): ...`, `chore(scope): ...`) and NEVER contain `Co-Authored-By`, `Generated by`, or attribution trailers.
- **No unverified green claims**: Verify exact compilation/test gates matching the change tier (`verify:ipc`, `verify:design`, `npx tsc --noEmit`, targeted Vitest/Cargo) after the final edit.
- **Explicit human push approval**: Always stop and present the commit plan, SHA(s), branch target, `git diff --stat`, and observed test results, requesting explicit approval before executing `git push`.

## Decision Gates

| Situation | Action |
|---|---|
| `audit-references.mjs --check` fails or flags any file | HALT immediately; report exact `file:line` matches and rewrite to Kite-native terminology. |
| Working tree mixes multiple features or `.kite/` files | Group explicit file paths into compilable ~400-line work units; leave unrelated/internal paths unstaged. |
| Target branch is `main` or `master` | Warn explicitly and confirm whether the user wants a feature branch or explicit confirmation before pushing. |
| Any required IPC, design, `tsc`, or test gate fails | Block commit/push and return exact failing commands and diagnostics. |

## Execution Steps

1. Inspect `git branch --show-current`, `git status --short`, and `git diff --stat`.
2. Verify zero forbidden files (`.kite/`, secrets, temporary logs) are staged (`git diff --cached --name-only`) and scan `git diff --cached` for `Co-Authored-By` or credentials.
3. Run `node .kite/sanitizer/audit-references.mjs --check` and confirm `[AUDIT CLEAN]`.
4. Run proportionate verification (`npm run verify:ipc`, `npm run verify:design`, `npx tsc --noEmit`, targeted `npx vitest run` / `cargo test`).
5. Present the exact slice ledger (files, Conventional Commit subject/SHA, verification summary, destination remote/branch) and wait for explicit user approval before running `git push`.

## Output Contract

Return: branch/remote target, `[AUDIT CLEAN]` verdict, staged/committed file slice & SHAs, exact observed check commands/results, and explicit confirmation prompt before `git push`.
