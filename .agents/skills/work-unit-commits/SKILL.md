## Activation Contract

Load before staging changes, splitting mixed working trees into commits, or planning pull requests / work-unit slices.

## Hard Rules

- **Explicit authorization**: never run `git commit`, `git push`, or destructive git operations unless explicitly requested by the user (or authorized inside an active ODD implementation workflow on a feature branch).
- **One work unit per commit**: commit by cohesive behavior, fix, migration, or doc slice—never split artificial `models / services / tests` commits where intermediate commits fail to compile.
- **Keep tests and docs paired**: behavioral tests and user-facing/ODD docs travel in the same commit as the code they verify or specify.
- **Conventional Commits strictly**: `feat(scope): ...`, `fix(scope): ...`, `docs(scope): ...`, `refactor(scope): ...`, `test(scope): ...`, `chore(scope): ...`.
- **ZERO AI attribution**: NEVER add `Co-Authored-By`, `Generated by`, or similar trailers to any commit message.
- **Clean-room check before stage/commit**: locally run `node .kite/sanitizer/audit-references.mjs --check` before staging/committing; in cloud environments without `.kite/`, inspect diff manually for external project leaks.

## Decision Gates

| Situation | Action |
|---|---|
| Dirty tree mixes unrelated features/fixes | Group files along dependency seams so every commit compiles independently. |
| PR / commit approaches ~400 authored changed lines | Treat ~400 lines as a planning heuristic (never delete comments, tests, or blanks to game line count). Slice by cohesive feature unit if separable. |
| Unverified code edits remain in working tree | Run compilation + focused tests (`tsc --noEmit`, `vitest run`, `cargo test` locally) before committing. |
| Intermediate commit changes shared interface | Include all callers or verify the intermediate commit compiles cleanly in isolation. |

## Execution Steps

1. Inspect `git status` and `git diff --stat` to identify cohesive feature/fix boundaries.
2. Verify recent commit convention via `git log --oneline -5`.
3. Stage only files belonging to the target work unit.
4. Run verification (`audit-references.mjs --check` locally + compile/test checks).
5. Commit with a concise outcome-oriented Conventional Commit message and zero attribution trailers.

## Output Contract

Report commit SHA, Conventional Commit subject, included work-unit scope, verification results, and any files intentionally left unstaged or pending push authorization.
