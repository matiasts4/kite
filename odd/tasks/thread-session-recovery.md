# Persistent Session Recovery, Model-Change Respawn & Failure Propagation

Objective: Ensure persistent turn failures (including quota exhaustion errors) emit `TransportEvent::TurnFailed` cleanly instead of `TurnEnded`, and ensure `SessionManager` verifies backing transport liveness and control compatibility so switching models or retrying after a crashed provider process cleanly respawns the session instead of writing into a dead pipe.
Branch: `feat/response-thread`. Do not commit on `main`.
Delivery strategy: `ask-on-risk` on `feat/response-thread` (leave shared working-tree files unstaged alongside pending concurrent work until review/commit).
Test runner: `cargo test --manifest-path src-tauri/Cargo.toml chat::`, `npx vitest run src/components/views/chat`, `npx tsc --noEmit`, `node .kite/sanitizer/audit-references.mjs --check`.

## Specs

### S1 — Persistent Frame Failure Propagation & `UsageLimit` Classification
Addresses root cause where Antigravity `429 RESOURCE_EXHAUSTED` results returned `Notice` + `TurnEnded` (settling runs as `"completed"`) and `spawn.rs` dropped error reasons on pre-write transport failures.

1. **`parse_antigravity_line` Failure Propagation (`persistent/antigravity.rs`):**
   - For `"result"` frames where `/result/status` is not `"SUCCESS"` (case-insensitive) OR `/result/error` is non-empty, keep emitting informative `Notice` events and emit **`TransportEvent::TurnFailed(reason)`** as the terminal turn event instead of `TransportEvent::TurnEnded`.
   - For `"error"` frames, emit informative `Notice` plus **`TransportEvent::TurnFailed(reason)`** so mid-turn protocol/quota errors terminate the turn as failed rather than stalling or appearing successful.
2. **`UsageLimit` & Reset Window Parsing (`turn_pipeline/coalescer.rs`):**
   - Extend `classify_turn_failure` so `"resource_exhausted"` and `"resource has been exhausted"` match `TurnFailure::UsageLimit`.
   - Parse reset duration hints (`"Resets in XhYmZs"`) into `reset_at_unix_ms` when present.
3. **Transport Reject Reason Preservation (`runtime/spawn.rs`):**
   - When `managed_send_prepared` fails with `ManagedSendError::Turn` (or non-before-turn error), pass `error.reason()` to `finish_run` instead of `""` so error history and diagnostics record the cause.

### S2 — Transport Liveness & Control Reconciliation in `SessionManager`
Addresses root cause where `SessionManager::attach` returned `AlreadyAttached` for any non-`Closed` session (even dead or `Failed` ones, or with a different CLI model) and `send_turn` attempted `write_turn` onto an EOF child process.

1. **Transport Introspection Trait Methods (`session/types.rs`):**
   - Add default-implemented methods on `SessionTransport`:
     - `fn is_alive(&self) -> bool { true }`
     - `fn controls(&self) -> Option<PersistentControls> { None }`
     - `fn update_controls(&mut self, _next: &PersistentControls) -> bool { true }`
2. **Per-Transport Implementations (`persistent/{antigravity,grok,opencode}.rs`):**
   - `AntigravitySession`: `is_alive` returns `false` once spawned and `stopping || eof || stdin.is_none() || reader finished`. `update_controls` accepts updates in-place only before first spawn (`spawns == 0`); once spawned, returns `self.controls == *next` so switching `model`, `effort`, or `permission_mode` triggers a clean respawn with new CLI flags.
   - `GrokSession`: `is_alive` reflects process/EOF state (`spawns == 0 || (!stopping && !eof && ...)`). `update_controls` updates `model` and `effort` in-place while keeping the running `agent stdio` process (`permission_mode` mismatches return `false` for respawn).
   - `OpenCodeServerSession`: stores `controls`, reports server liveness via `!stopping && !server_eof && server.is_some()` once spawned, and updates `model` / `effort` / `model_arg` in-place (`true`) because turns forward `--model` per turn.
3. **Session Reconciliation (`session/manager.rs`):**
   - In `SessionManager::attach`: replace an existing session (preserving `resume_handle` when same canonical driver & `connection_id` and non-empty handle) whenever:
     - `!existing.transport.is_alive()`
     - `matches!(existing.record.state, SessionState::Failed | SessionState::Resumable | SessionState::Interrupted | SessionState::Closed)`
     - `driver`, `connection_id`, `working_directory`, or `mode` changed (dropping `resume_handle` if driver or connection changed)
     - incoming `transport.controls()` returns `Some(next)` and `!existing.transport.update_controls(&next)`
   - When `Existing` remains valid (`is_alive()` and compatible controls), retain it cleanly (`AttachOutcome::AlreadyAttached`, `spawn_count` unchanged).
   - In `SessionManager::start` and `send_turn`: verify `session.transport.is_alive()` before reusing a persistent process (`Idle`/`Completed`); respawn via `Reaped` + `resume_handle` fallback if the backing process died without a prior `Exit` poll; and if `write_turn` fails when `!session.transport.is_alive()`, mark `session.record.state = SessionState::Failed`.

### S5 — Interrupted-Turn & Restart Settlement Across Persistence, Manual Stop, and Subagent Reconciliation

- Leaving `thread.status == "running"` also caused `subagents/antigravity.rs::reconcile_antigravity_subagents_with_discovered` to regress already-completed `SubagentRun` / `subagentMeta` records back to `"running"` whenever `needs_antigravity_transcript_reconcile` triggered (for instance from a synthetic `"conversationId"` captured from `run_command`/`read_file` stdout in parent `transcript_full.jsonl`).

     - Restores `status: "waiting"` when `pendingApproval` or `pendingUserInput` is present, otherwise `"idle"`.
     - Sets `stoppedByBuilder: true` when `stopped_by_user && !waiting_for_permission`, marks `implementing` plan slots `"interrupted"`, removes `QUIET_TURN_NOTE_TEXT`, sets `streaming: false` on every item, sets non-subagent in-flight items (`running` / `waiting` / `queued` / `inProgress` / `in_progress` / `pending` / `started`) to `"stopped"`, settles `"working"` swarm members to `"stopped"`, preserves already-terminal `subagentRuns` (`completed` / `failed` / `killed`), settles any non-terminal `subagentRuns` (including `waiting`, `queued`, `running`, `pending`, `inProgress`, `in_progress` — resolving to `completed` when `child_transcript_ended_with_final_response` holds, otherwise `killed`) and syncs **all** matching `subagent` items + `subagentMeta.status` (including orphaned items whose `subagentMeta.status` or `streaming` remained active after `run` settled), and finalizes provisional titles via `apply_derived_title_if_needed`.

   - Inside `threads::load_thread`, run `hydrate_antigravity_subagents_on_load` outside `threads()` lock and persist any reconciled changes back into `threads()` + SQLite when modified (keeping unmodified reads zero-write), and only call `heal_orphaned_running_thread(thread, false)` when `!is_thread_runtime_active(thread_id)` and `updatedAtUnixMs` exceeds a `5s` startup grace cutoff (settling non-`childThreadId` orphaned in-flight items/runs on `"idle"` / `"error"` threads only when no active transcript tailer or live child thread runtime exists).

### S6 — Spurious Post-Reply Stream Interruption Suppression, Active-Turn Disk Verdict Check & Cascaded Child Stop
Addresses root causes verified in `eb5fc35a-0a35-46df-baa1-e5c8b783e2a4` (transcript `f614142d`) and sibling `e3cc22c9-85bf-4fe0-b7a1-5ef9ca7a407b` (`7fbf8c75`):
- Once an Antigravity trajectory recorded an earlier `ERROR_MESSAGE` (`step 163` / `step 191`), subsequent clean turns (`PLANNER_RESPONSE status=DONE` on disk with zero new `ERROR_MESSAGE` steps) received a delayed `{"event":"result","result":{"status":"ERROR","error":"The stream was interrupted. Please continue the task you were working on."}}` frame 16–44s after replying cleanly. Because `pump_persistent_session` did not inspect the active turn transcript verdict on `!ok`, and `post_reply::CONNECTION_MARKERS` omitted `"the stream was interrupted"`, every subsequent reply ended with `turnFailure`, `"status": "error"`, and a red error banner (`"The stream was interrupted. Please continue the task you were working on."`).
- Additionally, stopping a conversation via `ChatView` single-thread Stop (`SingleThreadPane` lacked `onStopThread`) or `runtime/turn.rs::cancel_turn` did not cascade cancellation into active `childThreadId` subagents / working Swarm members.

1. **Antigravity Active-Turn Disk Verdict Check & Error-Notice Buffering (`runtime/antigravity_fallback.rs`, `runtime/turn.rs`):**
   - Add `is_transient_stream_interruption(error)` (excluding immediate quota/auth/5x-network errors) and `verify_completed_turn_on_disk_in_dir` / `verify_completed_turn_on_disk_for_session` that slices strictly the active turn (`slice_active_turn_steps`) and checks `analyze_turn_verdict(&turn_slice, last_stdout_step_index, true) == TranscriptVerdict::Completed { .. }`.
   - Buffer `"notice"` events within each `pump_persistent_session` poll batch before emitting them. When an `antigravity` / `agy` turn returns `!ok` with `is_transient_stream_interruption(&error)` and `verify_completed_turn_on_disk_for_session` confirms the active turn completed cleanly on disk: run catch-up if stdout missed the response, promote `ok = true` with empty error, suppress the matching `"antigravity ended the turn with status ERROR"` / `"antigravity error: ..."` notices in that batch, keep the persistent session intact, and settle cleanly as `"idle"`.
2. **Stream-Interruption Marker in `post_reply.rs` (`runtime/post_reply.rs`):**
   - Add `"the stream was interrupted"` and `"stream was interrupted"` to `CONNECTION_MARKERS` so genuine stream interruptions occurring *after* a delivered final reply downgrade cleanly via `absorb_connection_loss_after_reply` and `heal_persisted_connection_loss_after_reply` into `CONNECTION_LOST_AFTER_REPLY_NOTE` (`status: "idle"`), while genuine mid-turn interruptions with no delivered reply preserve their failure banner and retire the broken session via `is_connection_failure`.
3. **Cascaded Parent-to-Child Cancellation (`runtime/turn.rs`, `runtime/settle.rs`):**
   - In `cancel_turn(thread_id)`, collect active non-terminal `childThreadId`-backed subagents (`subagentRuns` + non-stopped/killed `swarmState.members`) while briefly locking `threads()`, drop locks, and cancel each distinct child via `cancel_subagent_thread` / `cancel_turn`.
   - In `finish_run`, pass `settle_async_children = stopped` to `settle_in_flight_thread_work` so user Stop settles child runs to `"killed"` and working Swarm workers to `"stopped"`, while normal (`stopped = false`) parent turn yields preserve active async children (`S5`).
